`{{pkg}}` is a TypeScript framework for HTTP API services on Node.js. Beyond routing and validation, it ships
the parts every production service needs and usually gets from separate tools: an operations console, a
deployer with blue-green releases and backups, deploy review, signed service-to-service calls and log
redaction for payment data.

```bash
npm install {{pkg}}
```

Node.js 24 or later is required (the supported LTS lines).

## How the parts fit together

One `APIService` runs your endpoints and the built-in routes on the same port. The deployer is the same
framework running on the target server with the `deployer` option, so there is no separate agent to install.

| Route | Purpose | Who uses it |
|---|---|---|
| your endpoints | your API | your clients, through your [interceptor](/docs/interceptors) |
| `liveness`, `readiness` | health checks | load balancers and orchestrators |
| `doc/*` | [API documentation](/docs/api-documentation) | developers and partners |
| `sm/*` | [monitor console](/docs/monitor) | your operations team, with 2FA |
| `pckg/*` | [deployer](/docs/deployer), if configured | CI and developers, with signed requests |
| `review/*` | [deploy review](/docs/deploy-review), if configured | reviewers, with 2FA |

The built-in routes are always hidden from the API documentation.

## Design principles

- **Secure defaults, explicit configuration.** Passwords are stored only as scrypt hashes, 2FA can’t be
  turned off for the monitor, and request signing uses key pairs so the server holds nothing worth stealing.
- **One envelope.** Every response has the same shape, success or error:

  ```jsonc
  { "data": { … }, "responseTime": 4, "endpoint": "/api/v1/users/get", "version": "1.2.0", "traceId": "…" }
  { "error": { "code": 401, "message": "Unauthorized", "httpStatus": 401, "details": "…" } }
  ```

- **Stated limits.** The [security model](/docs/security) lists what the framework doesn’t do as clearly
  as what it does.

<Callout kind="security" title="Using it in a PCI DSS environment">
The framework helps with specific requirements — MFA, lockout, session limits, redaction, change control —
but compliance is assessed for your whole environment. See the [PCI DSS mapping](/docs/pci-dss).
</Callout>
